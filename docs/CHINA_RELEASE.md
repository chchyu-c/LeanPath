# 中国大陆上架合规与提审清单

> 用户选择「中国大陆为主」，因此 **Google Play 流程不适用**。
> 本文件是 `docs/checklists/` 与 `references/release-checklist.md` 的国内补充，两者要一起看。
> 政策会变动，提交前请以工信部、各商店开放平台与 App Store Connect 的最新规则为准。

## 一、三张硬门槛（缺一不可，建议提前 1–2 个月启动）

| 门槛 | 说明 | 谁要 |
|---|---|---|
| **软件著作权登记证书** | 国内 Android 商店普遍要求上传《计算机软件著作权登记证书》或等效权属证明；名称需与应用名/包名一致 | 华为、应用宝、小米、OPPO、vivo 等多数商店 |
| **App 备案（工信部）** | 依据工信部移动互联网应用程序备案要求，境内运营的 App 须完成备案并取得**备案号**；由接入商/分发平台代为提交。未备案的 App 不得上架或提供下载，中国区 App Store 也要求填写备案号 | 全渠道，含 iOS 中国区 |
| **可访问的隐私政策 URL** | HTTPS、内容完整、App 内常驻入口；需含个人信息收集清单与第三方共享清单 | 全渠道 + 审核 |

另外：若隐私政策/客服页使用自有域名，域名需完成 **ICP 备案**；企业主体需营业执照，
个人主体在部分商店受限（健康类应用通常要求企业主体）。

## 二、商店矩阵

| 渠道 | 提交物 | 特殊要求 | 自动化 |
|---|---|---|---|
| 华为应用市场 | 签名 APK / AAB | 软著、备案号、隐私政策、权限清单、分级、隐私标签 | AppGallery Connect Publishing API（可自动化） |
| 小米应用商店 | APK | 软著/授权、备案号、权限用途说明、适龄提示 | 后台上传为主 |
| OPPO 软件商店 | APK | 备案号、隐私政策、权限说明、内容分级 | 后台上传为主 |
| vivo 应用商店 | APK | 备案号、软著、隐私合规自检 | 后台上传为主 |
| 应用宝（腾讯） | APK | 软著、备案号、隐私政策、工信部备案截图 | 后台上传为主 |
| App Store 中国区 | IPA | Apple Developer 企业账号、备案号、隐私政策 URL、健康类分级、审核备注 | TestFlight + App Store Connect |

> 本仓库 `store-listing/google-play/` 目录是脚本生成的通用模板，**国内首发不使用**，
> 保留作为后续出海的参考。`store-listing/china/` 才是本次提交用文案。

## 三、健康/减肥类审核红线（本项目最容易踩）

1. **不得作疗效或效果承诺**：「保证瘦 X 斤」「最有效」「第一」「唯一」「根治」全部禁用（广告法）。
2. **不得使用医疗术语**：治疗、诊断、处方、临床、疗效；分类选「健康/运动」而非「医疗」。
3. **必须带免责声明**：`本应用不提供医疗建议，非医疗器械；减重效果因人而异`（已写进
   `i18n/l10n` 与商店文案），App 内与商店描述都要出现。
4. **参考体重曲线**必须标注「参考，非承诺」（代码里已按此实现）。
5. 不得展示未经授权的名人身材对比图、前后对比照或第三方商标。
6. 不得为未成年人提供减重目标引导；年龄分级建议 18+ 或至少标注家长指导。
7. 若后续接入饮食/热量数据库或 AI 建议，可能被认定为医疗健康信息服务，需额外资质。

## 四、权限与隐私专项

- 按 `docs/PERMISSIONS.md` 逐条提交「权限清单与用途说明」，
  尤其是 `ACTIVITY_RECOGNITION`（身体活动，敏感权限）与 `SCHEDULE_EXACT_ALARM`。
- 敏感个人信息（体重、步数）**单独同意**，申请前弹窗说明目的（代码已实现弹窗）。
- 首启同意隐私政策前不得初始化任何采集；数据导出/删除入口见 `docs/PRIVACY.md` 待办清单。
- 上架前做一次隐私合规扫描：未声明权限、过度采集、SDK 清单、后台静默采集。
- 本版本无账号体系，隐私政策中需明确说明「不提供账号注册，故无账号注销」；
  若后续接入登录，必须补注销入口。

## 五、推送与保活（本方案的优势）

- **不使用 FCM / 厂商推送 SDK**：提醒全部是系统本地通知，由 AlarmManager /
  UNUserNotificationCenter 调度，因此不受推送通道可达性影响，也少一批第三方 SDK 申报。
- 代价：国内厂商 ROM 的省电策略仍可能拦截精确闹钟，必须做
  「自启动 + 关闭电池优化」引导（已实现一键跳转）与各品牌真机实测。
- 若未来要做运营推送，再评估个推/极光 + 厂商通道，并补第三方 SDK 清单与单独同意。

## 六、iOS 中国区差异

- 证书/描述文件、TestFlight、App Store Connect 流程与海外基本一致。
- **额外**：在 App Store Connect 的 App 信息里填写 App 备案号；审核备注中说明
  本地通知与运动感知的用途，避免被判定为后台滥用。
- Info.plist 不声明 `UIBackgroundModes`（本地通知不需要），降低审核问询概率。
- 不申请 Critical Alerts（需 Apple 特殊授权），见 `docs/ARCHITECTURE.md`。

## 七、提审前 Checklist

- [ ] 软著证书、App 备案号已取得并归档
- [ ] 隐私政策 URL 可访问，App 内入口 + 双清单已完成（`docs/PRIVACY.md` 待办）
- [ ] 商店文案按 `store-listing/china/metadata.md` 填写，无绝对化/医疗用语
- [ ] 应用图标 512×512（Android）、1024×1024（iOS）、启动图、截图按规格产出
- [ ] 权限清单与用途说明、内容分级、适龄提示
- [ ] release 包已关闭调试日志、移除测试入口、开启 R8 混淆
- [ ] 崩溃监控（建议 Bugly / 火山 APM 等境内服务）接入或明确首版豁免
- [ ] 华为/小米/OPPO/vivo 真机：锁屏 30 分钟准点响铃、重启后恢复、通知按钮打卡
- [ ] 功能开关与回滚预案就绪（`docs/feature-flags`）
- [ ] 版本号 / versionCode 递增、AAB 与 APK 用同一 keystore 签名

## 八、建议时间线

```
T-8 周  启动软著 + App 备案；确定企业主体与域名 ICP 备案
T-6 周  隐私政策法务定稿；App 内合规入口补齐
T-4 周  内测（蒲公英 / TestFlight），厂商 ROM 保活实测
T-2 周  商店后台建应用、上传素材、填分级与权限说明
T-1 周  CI 打 release tag，归档产物，灰度 10%
T-0     各商店提交审核 → 过审后手动发布 → 观察崩溃与提醒准时率 → 全量
```

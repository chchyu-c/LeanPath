# 隐私政策与个保法落地要点（模板骨架，需法务定稿）

> 本文件是给法务/合规的输入，不是可直接发布的最终文本。
> 上线前必须替换为真实可访问的 HTTPS URL，并在 App 内提供常驻入口。

## 一、必须写清的内容

1. **处理者信息**：公司名称、统一社会信用代码、注册地址、联系方式、个人信息保护负责人邮箱。
2. **收集清单（第一清单）**

| 数据项 | 是否敏感 | 目的 | 存储位置 | 是否上传 | 保留期限 |
|---|---|---|---|---|---|
| 起始/目标体重、计划天数 | 健康类敏感个人信息 | 生成减肥路径 | 本机 SharedPreferences / UserDefaults | ❌ | 用户删除计划或卸载为止 |
| 步数、活动状态（步行/静止） | 健康类敏感个人信息 | 判定今日任务是否在进行 | 本机内存 + 打卡记录 | ❌ | 用户删除数据或卸载为止 |
| 打卡记录、连续天数 | 一般个人信息 | 展示进度 | 本机 | ❌ | 同上 |
| 饮食方案选择、三餐打卡记录（按计划/换餐/没吃）、执行统计 | 健康类敏感个人信息 | 展示饮食计划、统计按计划执行天数、三餐提醒 | 本机 SharedPreferences / UserDefaults | ❌ | 用户删除计划或卸载为止 |
| 通知调度时间、运动提醒设置、三餐时间与提前分钟数 | 一般个人信息 | 定时提醒 | 本机 | ❌ | 同上 |
| 设备时区 ID | 一般 | 精确调度本地通知 | 内存 | ❌ | 当次会话 |

3. **第三方共享清单（第二清单）**：MVP 阶段应为「无」。
   后续接入崩溃监控/推送/统计 SDK 时，须列明 SDK 名称、主体、收集字段、目的、隐私政策链接，
   并签订数据处理协议。
4. **敏感个人信息单独同意**：体重、运动数据与饮食记录在首次录入/开启感知前，用独立弹窗告知
   目的与必要性，不得与「同意隐私政策」捆绑；用户可拒绝并继续使用计划查看/手动打卡。
   饮食建议为内置静态内容，**不采集**用户实际吃了什么、不拍照、不读取健康平台数据；
   三餐打卡只记录「按计划 / 换了别的 / 没吃」三态与时间戳。
5. **权限说明**：逐条对应 `docs/PERMISSIONS.md`，写明用途与拒绝影响。
6. **用户权利实现**：
   - 查看/导出：设置页导出计划与打卡 JSON（**待实现**）
   - 更正：编辑计划（已有）
   - 删除：删除计划/清空数据（**待实现**）
   - 撤回同意：设置页关闭提醒与感知（已有）
   - 注销账号：MVP 无账号体系，需在政策中说明「我们不提供账号注册，因此无账号注销」；
     若后续接入登录，**必须**提供注销入口（App Store 与个保法均强制）。
7. **未成年人**：本应用面向 18 岁以上用户，不面向儿童；不投放个性化广告，不做用户画像。
8. **数据安全**：本地存储、R8 混淆、无明文密钥；如后续上云则境内存储 + TLS 1.2+ + 证书绑定。
9. **政策更新**：变更时 App 内公告并重新取得同意。

> 如有基础疾病、食物过敏、慢性病或处于特殊生理阶段，请咨询专业人士后再开始运动与饮食调整。

## 四、禁止事项

- 不得宣称「保证减 X 斤」「最有效」「唯一」「第一」等绝对化或疗效承诺（广告法 + 商店审核）。
- 不得使用「治疗」「诊断」「处方」等医疗术语。
- 不得在未单独同意前把体重/步数写入日志或上传。
- 不得接入未经申报的第三方 SDK。
